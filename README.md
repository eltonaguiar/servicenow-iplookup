# ServiceNow IP Lookup — `RESTMessageV2` example

A scoped ServiceNow application (`IPLookup`, scope `x_1569490_iplookup`, v1.0.0) that calls
[ipinfo.io](https://ipinfo.io/) from server-side JavaScript with `sn_ws.RESTMessageV2` — the
simplest complete outbound-REST sample in the ServiceNow portfolio: one REST Message, one HTTP
method, one variable, one Fix Script. No MID Server, no auth, nothing to configure but a URL.

Part of [eltonaguiar/ServiceNow_Portfolio](https://github.com/eltonaguiar/ServiceNow_Portfolio)
(entry **#7**).

Try the endpoint the app calls, to see the shape of the response before touching ServiceNow:
<https://ipinfo.io/8.8.8.8/json>

## The call

```javascript
var r = new sn_ws.RESTMessageV2('x_1569490_iplookup.IPInfo', 'Default GET');
r.setStringParameterNoEscape('ipaddress', '8.8.8.8');
var response = r.execute();
var responseBody = response.getBody();

// Throw the successful response so the payload lands in the modal dialog —
// the quickest way to see the raw JSON with no logging or table setup.
throw "Elton was here! Response: " + responseBody;
```

A Fix Script only surfaces output when something is thrown, so throwing the 200 response body
turns the modal into a response viewer. That is test scaffolding, not production error handling:
in a Business Rule or Script Include you would check `getStatusCode()` and parse `getBody()`
instead.

## Branch model

ServiceNow's source-control linkage created this repository, and it keeps committing to its own
branches. `main` is not one of them:

| Branch | What it holds | Written by |
|---|---|---|
| **`main`** | this snapshot, published so the repo is browsable | pushed by hand |
| `latest` | the export the instance last wrote (its root `README.md` is a one-line placeholder made in the GitHub web UI — superseded by this file) | ServiceNow |
| `sn_instances/dev213089` | the branch Studio commits to for this instance | ServiceNow |

If the app changes in the instance, `sn_instances/dev213089` and `latest` move first; `main`
follows when someone re-publishes it. Treat the instance branches as the source of truth.

## Rebuilding it by hand

You do not need the XML to reproduce this — three records are enough:

1. **System Web Services → Outbound → REST Message**: name `IPInfo`, endpoint
   `https://ipinfo.io/`, no authentication.
2. Add an HTTP method: name `Default GET`, method `GET`, endpoint
   `https://ipinfo.io/${ipaddress}/json`, authentication "inherit from parent".
3. On the method, add a variable `ipaddress` with default `8.8.8.8`.
4. Run the Fix Script — the modal shows the JSON for `8.8.8.8`.

## Notes

- **Do not hand-edit the app XML.** It is generated from the instance and covered by
  `checksum.txt`; a hand-made edit or a merge of mixed revisions makes the app un-importable
  (ServiceNow's generated `README.md` inside the app folder documents the recovery).
- Auth belongs on the REST Message (or an auth profile) with the method left on
  `inherit_from_parent`, so changing endpoints does not mean re-entering credentials.
- Nothing here routes through a MID Server, so the endpoint must be reachable from the instance
  itself — the opposite constraint to the JDBC and export-set samples in the portfolio, which
  need `win11-mid`.
