# ServiceNow IP Lookup — `RESTMessageV2` example

A scoped ServiceNow application (`IPLookup`, scope `x_1569490_iplookup`, v1.0.0) that calls
[ipinfo.io](https://ipinfo.io/) from server-side JavaScript with `sn_ws.RESTMessageV2`.

It is the outbound-REST counterpart to the Remote Table sample in the portfolio: nothing here
needs a MID Server, so the endpoint must be reachable from the instance itself.

> **This `main` branch is a browse-friendly snapshot** of the app as most recently exported by
> ServiceNow (the `latest` branch, `6d3b744`). Studio still writes to `sn_instances/dev213089`;
> treat that branch as the source of truth if the two ever differ.

## What is in the app

| Record | Value |
|---|---|
| `sys_app` | `IPLookup` · scope `x_1569490_iplookup` · v1.0.0 · `js_level: es_latest` |
| `sys_rest_message` | `IPInfo` → `https://ipinfo.io/` · `no_authentication` · access `package_private` |
| `sys_rest_message_fn` | `Default GET` → `GET https://ipinfo.io/${ipaddress}/json` · auth `inherit_from_parent` · no MID Server |
| `sys_rest_message_fn_parameters` ×3 | `ipaddress`, default `8.8.8.8` |
| `sys_scope_privilege` ×4, `sys_user_role` ×2 | cross-scope / role access the app needed |
| `sys_script_fix` `Elton Test Integration` | the call below |

## The call

```javascript
var r = new sn_ws.RESTMessageV2('x_1569490_iplookup.IPInfo', 'Default GET');
r.setStringParameterNoEscape('ipaddress', '8.8.8.8');
var response = r.execute();
var responseBody = response.getBody();

// Throw the successful response so the payload lands in the modal dialog —
// the quickest way to see the raw JSON with no logging or table setup.
throw "Elton was here! Response: " + responseBody;
```

A Fix Script's output is only surfaced when something is thrown, so throwing the 200 response
body turns the modal into a response viewer. That is test scaffolding, not production error
handling — in a Business Rule or Script Include you would parse `getBody()` and handle
`getStatusCode()` instead.

## Rebuilding it by hand

If you would rather not import the app, the three records are enough:

1. **System Web Services → Outbound → REST Message**: name `IPInfo`, endpoint
   `https://ipinfo.io/`, no authentication.
2. Add an HTTP method: name `Default GET`, method `GET`, endpoint
   `https://ipinfo.io/${ipaddress}/json`, auth "inherit from parent".
3. Add a variable `ipaddress` with a default of `8.8.8.8`.
4. Run the Fix Script with your own IP address, or call the message from a Business Rule /
   Script Include using the two lines above.

Auth, when you need it, belongs on the REST Message (or an auth profile) with the method left on
`inherit_from_parent` — then changing endpoints does not mean re-entering credentials.
